# Inbox

[User guide](README.md) · [简体中文](../zh-CN/inbox.md)

Open **Inbox** in the sidebar for questions and approvals that real tasks need you to handle.

## Handle a request

1. Open pending items and identify the Bot and task.
2. Expand the question, command, installation plan, URL, or external-tool arguments.
3. Answer, confirm, allow, or decline as appropriate.
4. Check the handled state, then return to the conversation to observe execution.

A desktop-notification link may focus a particular request. Return to all items to see the complete list.

## Interpret status

- Awaiting answer: more information is needed.
- Awaiting confirmation: permission is needed for one operation.
- Answered, allowed, or declined: the request has been handled, not necessarily the whole task completed successfully.
- Withdrawn or interrupted: the old request no longer accepts a reply.

When submission is uncertain, check connectivity and use the original request's verification or retry action. Do not create another copy because feedback was not immediate.

## Related surfaces

Inbox mainly handles questions and approvals. Read ordinary task outputs in the Bot's conversation or [history](conversations.md). Use [Tasks](tasks.md) for a durable workspace-wide work list.

Configure [desktop notifications](notifications.md) to discover background requests. Notifications are entry points; the actual request and execution result determine the final state.
