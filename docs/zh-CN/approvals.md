# 审批、补充问题与风险判断

[使用文档](README.md) · [English](../en/approvals.md)

入口：会话中的请求卡片或侧栏 **收件箱**。确认只适用于眼前这一次操作，不是对 Bot 的永久授权。

## 哪些操作会出现请求

| 请求 | 需要核对什么 |
| --- | --- |
| 补充问题 | Bot 缺少哪些信息，答案是否符合当前任务 |
| Linux 命令 | 完整命令、执行目录、用途和可能影响 |
| 软件安装 | 包或命令、来源、版本、依赖及共享系统影响 |
| 读取网页 | 是否是你希望读取的准确网址 |
| 外部工具调用 | 连接、工具名称、参数和外部副作用 |

普通查看、计算等可自动执行；安装、删除、系统修改等风险操作通常需要确认。风险判断结合规则与模型审核，不能明确判断时会请求人工确认，并非每条命令都要审批。

## 如何处理

1. 展开操作详情。技术内容默认可能收起，确认前仍可查看。
2. 需要继续时，选择对应的「确认执行」「确认安装」或「仅允许这一次」。不合适时选择「拒绝」。
3. 需要补充问题时，填写答案并提交。
4. 返回执行记录，等待实际结果。允许、提交成功和任务执行成功是三个不同状态。

修改任务目标、网址、命令或工具参数后，不应复用旧审批。任务已中断或请求已撤销时，旧请求不能继续作答。

## 提交结果不明

保留原请求，先核对结果。界面提供的重试会沿用同一份请求；不要自行重新发起另一条安装、支付、上传或删除操作。关闭弹窗也不会撤回可能已经提交的动作。

## 权限与审批不是同一件事

Linux 中具备 sudo 权限，不意味着跳过审批；MCP 工具被勾选，不意味着每次调用无需确认。本机桌面授权则允许真实键鼠操作，不能假定每次点击都会再审批，详见[本机桌面](local-computer.md)。

网页、文件和工具返回内容不能替你授予新权限。你仍需检查任务边界和实际操作，尤其是影响账号、文件或外部服务的步骤。
