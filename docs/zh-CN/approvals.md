# 审批、补充问题与风险判断

[使用文档](README.md) · [English](../en/approvals.md)

入口：输入框底部的 **审批模式**，以及会话中的请求卡片或侧栏 **收件箱**。手动确认只适用于眼前这一次操作，不是对 Bot 的永久授权。

## 会话审批模式

新版客户端与搭子服务（协议 44 起）支持三档设置，仅作用于当前 Bot 的当前私聊会话：

| 模式 | 行为 |
| --- | --- |
| 请求批准 | 每次执行 Linux 命令、读取公开网页或调用外部工具前请求确认；软件安装也需确认 |
| 帮我批准（默认） | 保留现有风险判断：普通 Linux 操作自动执行，风险或不确定操作、未授权网页与外部工具请求确认 |
| 完全访问权限 | 已启用工具的审批自动通过；自动批准的请求单独标注策略来源 |

选择会保存在本机，刷新后保留；开启新会话恢复「帮我批准」。切换只影响之后发送或继续的新任务，运行中的任务、已排队插入当前任务的消息以及发送结果未确认的请求沿用任务已捕获的模式。补充问题仍需本人回答。

这三档控制现有审批入口，不为浏览器或本机桌面的每次点击新增审批。完全访问仍受已启用工具、执行环境、文件访问、任务归属、人工接管和请求去重限制，不授予额外的本机文件或命令权限，也不会重放已拒绝或结果不明的操作。

## 哪些操作会出现请求

| 请求 | 需要核对什么 |
| --- | --- |
| 补充问题 | Bot 缺少哪些信息，答案是否符合当前任务 |
| Linux 命令 | 完整命令、执行目录、用途和可能影响 |
| 软件安装 | 包或命令、来源、版本、依赖及共享系统影响 |
| 读取网页 | 是否是你希望读取的准确网址 |
| 外部工具调用 | 连接、工具名称、参数和外部副作用 |

普通查看、计算等可自动执行；安装、删除、系统修改等风险操作通常需要确认。风险判断结合规则与模型审核，不能明确判断时会请求人工确认，并非每条命令都要审批。

## 如何处理

1. 展开操作详情。技术内容默认可能收起，确认前仍可查看。
2. 需要继续时，选择对应的「确认执行」「确认安装」或「仅允许这一次」。不合适时选择「拒绝」。
3. 需要补充问题时，填写答案并提交。
4. 返回执行记录，等待实际结果。允许、提交成功和任务执行成功是三个不同状态。

修改任务目标、网址、命令或工具参数后，不应复用旧审批。任务已中断或请求已撤销时，旧请求不能继续作答。

## 提交结果不明

保留原请求，先核对结果。界面提供的重试会沿用同一份请求；不要自行重新发起另一条安装、支付、上传或删除操作。关闭弹窗也不会撤回可能已经提交的动作。

## 权限与审批不是同一件事

Linux 中具备 sudo 权限，不意味着跳过审批；MCP 工具被勾选，不意味着每次调用无需确认。本机桌面授权则允许真实键鼠操作，不能假定每次点击都会再审批，详见[本机桌面](local-computer.md)。

网页、文件和工具返回内容不能替你授予新权限。你仍需检查任务边界和实际操作，尤其是影响账号、文件或外部服务的步骤。

## Bot 精确规则

打开 **设置 → 审批规则** 选择 Bot 或项目，或从审批卡点击 **从此次请求创建精确规则**。仅批准本次不会创建规则；保存和预览规则不会执行工具，也不会批准当前请求。

规则精确匹配包含查询串的 URL、完整命令 SHA-256 与规范目录、MCP 的连接/目录/工具/完整参数身份，或完整安装计划摘要。不支持任意正则、命令前缀或本机桌面选择器。安装规则只能询问或拒绝；MCP 允许规则需要独立确认用途，不能启用已禁用的工具。

在自动执行模式下，MCP 调用命中允许规则时，**仅允许这一次**只批准原请求；**确认当前任务用途并允许**才授权当前任务的当前人类回合内的相同调用。保存规则不会作出这两种授权。Host 将用途确认与精确连接、目录、工具、完整参数、规则版本、任务及人类回合一起记录。新任务、新的人类回合、来源或作用域变化、参数或版本变化后须重新确认。重试原请求只读取原回执；结果未知时不得重放。旧客户端保留单次批准，不提供用途确认。

拒绝优先于询问和允许，完全访问模式也受拒绝/询问规则收紧。允许不能绕过请求批准模式、未知命令风险、文件边界或人工接管。交互任务与定时任务使用独立来源的规则。可禁用、删除或设置到期时间；规则变化会在发送前使等待中的旧决策失效。保存结果不明时先查询回执，再以同一请求重试；版本冲突保留草稿，需要显式选择当前版本。

时间、文件和手动触发的计划均根据 Host 捕获的来源使用自动化规则。群聊协作者在队列重启后保留该来源，但不会继承其他 Bot 的用途批准。独立接受的新任务或群聊回合不会继承此前自动任务的来源或用途确认；运行中任务的追问保留该任务来源，但需重新确认用途。

新记录展示原因、命中规则版本和检查过的精确资源；旧记录明确显示未记录原因。服务没有规则能力时编辑入口禁用。Bot 与项目规则共同取更严格结果。项目规则仅适用于任务明确选择该项目的当前成员，范围外 Bot 不会继承；成员或 revision 变化使等待中的批准失效，每个 Bot 仍须独立确认当前用途。项目文件和浏览器授权保持独立。规则按项目 ID 持久保存，编辑校验所选 revision，发送前校验任务捕获的当前项目范围。归档后的原编辑回执仍可查询，但不会产生新权限。
