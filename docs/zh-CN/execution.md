# 执行过程、计划与停止

[使用文档](README.md) · [English](../en/execution.md)

每次发送任务后，可以在回复上方展开「执行过程」。这里展示实际工具调用和状态；模型写出的计划或“完成了”不是唯一的执行凭证。

## 看懂当前状态

- 任务可能处于处理、工具执行、等待回答或审批、等待交还电脑、完成、失败或中断等状态。
- 「任务计划」是本次运行的步骤。进行中图标表示当前步骤，完成数量只反映这份计划。
- 工具记录可展开查看操作详情。命令、网址、安装和外部工具可能有不同的确认卡片。
- 模型已经开始回复，不代表后台工具全部完成；应结合最终状态和产物检查。

## 需要你介入时

打开[收件箱](inbox.md)或当前会话中的请求，补充答案、允许或拒绝操作。接管电脑后，这位 Bot 需要等你交还才能继续对应的电脑动作。

例如，让 Bot 生成报表时，可以检查：是否实际读取输入、是否执行计算、是否生成文件，以及最终文件是否能打开，而不只看自然语言总结。

## 停止任务

点击输入区上方的停止图标，请求取消当前任务。停止不会撤销已经完成的文件写入、网站提交、安装或外部服务操作。结果不明时，先查看原操作的回执或当前状态。

如果停止尚未确认，不要马上发送重复任务。确认原任务已经结束后，再说明要继续的部分；不要把“再做一次”当作状态查询。

## 计划、待办和定时任务的区别

| 功能 | 含义 |
| --- | --- |
| 本次任务计划 | Bot 对当前执行步骤的安排 |
| [共享任务](tasks.md) | 持久待办，保存本身不会执行 |
| [定时任务](schedules.md) | 到时为指定 Bot 提交一轮任务 |

历史执行记录供查看，不会重跑工具，也不沿用历史审批。新对话、停止电脑和恢复整个环境的影响也不同，分别见[聊天](conversations.md)、[Linux 电脑](linux-computer.md)和[环境恢复](recovery.md)。
