# Bot 群聊与协作

[使用文档](README.md) · [English](../en/groups.md)

入口：侧栏「你的 Bot」旁的 **创建 Bot 群聊**。群聊由已有 Bot 参与，不是邀请其他人的团队账号系统。

## 创建和发送

1. 先创建需要参与的 Bot。
2. 新建群聊，填写名称，选择 2–8 位成员并保存。
3. 选择一位接收成员，或选择全部可用成员。
4. 描述共同目标和各自分工，再发送消息。

例如：“先由研究员整理依据，再由写作搭档据此写一页摘要；发现缺失信息先指出。”选择多位成员时按顺序处理，不代表同时抢占同一屏幕。成员也可在本群按任务进行交接。

在消息中输入 `@` 可选择当前群成员；用方向键和 Enter（或 Tab）确认，Esc 关闭列表，Shift+Enter 仍用于换行。提及文字会保留在消息中。有提及时，只派发给被 @ 的 Bot，按首次提及顺序执行，同一成员重复提及只派发一次；没有提及时使用接收成员控件。已选提及在草稿重开和成员改名后仍绑定原 Bot；成员不可用时会阻止发送，需要删除或重新选择提及。同名成员请从列表选择具体 Bot；重试未确认的发送仍使用原接收对象。

## Bot 按任务建群

私聊中的当前任务需要不同角色配合时，Bot 可以查看已有可用 Bot 的名称和角色，选择 1–7 位搭档建群，自己自动加入。新群会出现在侧栏；搭档依次处理任务，发起者最后回群汇总。能独立完成的任务和普通问候无需建群。

群任务会保留各成员的分工、最终交付物和验收条件，包括发起者自己的收尾工作。成员对当前任务的最终回复会自动显示在群聊中。

Bot 只向群里提交当前任务的目标、必要背景和成员分工，摘要署名为发起 Bot。私聊历史、工作记忆和附件不会自动复制到群里；建群也不授予新的电脑或外部工具权限。群内成员不能再次调用建群工具，仍通过本群的任务交接协作。

同一任务及其重试只建立一个协作群。重复提交相同参数会返回原群，不重复派发；变更参数会被拒绝。重启后仍保留这份记录，已停止或归档的协作不会因重试重新启动。新的独立任务可以创建自己的协作群。

## 共享哪些上下文

群内对话共享，成员的工作记忆和个人工作区各自保留。群聊不会把所有成员的私聊和资料自动合并，也不会因为加入群聊而授予电脑或外部工具权限。

发送图片时，所选成员都需要支持图片的模型。群聊文件可在文件面板查看；消息中展示的文件数量可能少于全部产物。

## 编辑、复制和归档

进行中的协作结束或停止后，才能修改成员。停止本轮协作不会撤回已经产生的文件或外部操作。

「复制群聊」创建使用同一批现有 Bot 的空群聊，不复制聊天和附件。Bot 资料和设置仍是原来那几位 Bot 的，不会被复制成新成员。

[归档](archives.md)保留群聊历史、成员、文件和草稿；恢复不会自动派发旧消息，也不改变成员的私聊和电脑授权。

群聊独立的公共资料库与群聊定时任务尚未接入；需要这些功能时选择具体成员的[资料](knowledge.md)或[定时任务](schedules.md)。
