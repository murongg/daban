# 上下文、长期记忆与调用费用

[使用文档](README.md) · [English](../en/context.md)

聊天能保留记录，但模型每次能读取的内容有容量限制。理解下面几种内容，可以减少遗漏、重复指令和不必要的调用。

| 内容 | 作用 |
| --- | --- |
| 当前对话上下文 | 本次连续交流中供模型使用的消息和工具结果 |
| 历史记录 | 保存下来供查看的内容，不保证全部进入当前上下文 |
| 工作记忆 | 你明确保存的长期偏好，供后续任务使用 |
| 资料库 | 持久参考文档，按需查找和读取 |

## 长对话如何处理

上下文预算根据所选模型的配置而变化。较长运行可能整理或压缩旧上下文，以便继续处理新内容。压缩不是删除可见聊天，也不等于把对话自动写入长期记忆。

系统会先整理过大的工具文本；仍有压力时，再生成摘要并保留近期原文。保留量、摘要额度和缓冲会随模型容量与输出预算调整。整理工具结果本身不调用模型，生成摘要会产生额外用量。

更换模型连接、更新职责或技能等导致会话需要重建时，Bot 会从已保存记录恢复初始请求、适用的摘要检查点、任务状态和预算内的近期记录。被省略或缩短的内容带有回读引用；开启新对话后不会自动带回旧对话的上下文。

可以直接提出“回查上次工具输出里包含某个编号的原文”。Bot 能列出自己当前或历史任务的已保存工具结果，再按关键字和分页读取。只开放同一 Bot 和会话的可见文本，系统提示、私有 SDK 日志和思考过程不在这个入口中。执行记录本身未保存的内容或非文本产物，需要重新检查其原始来源。

需要精确数值、原话或先前文件时，让 Bot 再读当前原文并核对。需要开启独立工作时可新建对话；要长期保留的要求写入[记忆](memory.md)，材料放入[资料](knowledge.md)。

## 上下文和输出预算

在[模型设置](models.md)中核对上下文窗口与输出上限。错误填写过大值可能让服务拒绝请求，过小值可能过早限制任务。自动匹配只是参考，实际限制以当前服务为准。

当前请求、工具定义和图片也需要空间。输出额度过于接近上下文容量时，应降低输出上限或选用更大窗口。预算包含估算；摘要仍可能遗漏细节，精确数字和引用应回读原文。恢复的旧记录不延续旧审批，也不能作为当前屏幕或文件状态的证明。

## 调用和缓存

模型回复、部分连接验证、模型测试、定时执行及需要模型审核的操作都可能消耗 API 用量。网页下载成功不代表总结文章的模型调用免费。

缓存是否命中由供应商的机制和请求内容决定，Daban 不保证固定命中率或折扣。更换模型、修改职责和偏好、变化的工具目录等都可能影响可复用的请求前缀。清空历史或频繁改连接不应作为通用“提高缓存”方法。

当前不应假定提供完整的费用账单或自动月预算控制。到所用供应商查看实际计费；先用短任务验证，再安排高频自动执行。
