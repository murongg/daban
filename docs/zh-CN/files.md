# 工作区文件与预览

[使用文档](README.md) · [English](../en/files.md)

入口：Bot 工作区的 **文件** 面板。这里查看实际保留的工作文件，与聊天附件和资料库各有用途。

| 内容 | 用途 |
| --- | --- |
| 工作区文件 | 任务生成或需要继续处理的文件；Linux 环境中存在共享区域 |
| 聊天附件 | 本次消息的输入材料及已保留的附件 |
| 资料库 | 某位 Bot 长期保存的文本参考材料 |

## 查看和使用

1. 打开文件面板，刷新列表。
2. 点击文件查看可用预览；按需下载到本机。
3. 要交给模型处理时，选择加入消息，并补充处理要求。
4. 从会话中的文件结果打开内容时，也应核对当前文件，而不只看模型声称生成了什么。

例如：“根据附件生成一份 CSV，保存结果，并检查表头和行数。”任务完成后下载实际文件验证。

## 只读文件审阅

使用兼容的 Linux 执行服务时，新任务会在输入暂存后记录任务目录，并在已知工具调用排空后再次观察。从执行详情或文件面板打开「文件审阅」可比较保留的证据。发送前可明确选择最多八个已有共享文件；排队消息会固定这份选择，并等待新的执行，不扩大当前任务的范围。

项目任务审阅自己的私有任务目录，以及该项目共享区中明确选择的文件。选择绑定 Host、工作区、Bot、会话和项目修订。读取证据时仍检查原项目的当前授权；切换项目不会获得旧执行的读取权限。不支持项目审阅的 Guest 会报告不可用，不会改读原共享环境的同名文件。

审阅区分新增、修改、删除、未变和未知证据，并提供有界的 UTF-8 行差异。「检查当前状态」将新读取与保留的结束证据比较，不替换历史。普通预览和下载仍读取当前文件。基线缺失、不稳定读取、排除项及容量或时间限制都有明确说明；二进制文件仅提供大小和 digest 证据，不进行专业文档的语义比较。

两次观察不能证明变化由哪位 Bot 造成，也不能覆盖外部操作或证明后台写者已经结束。任务期间创建又删除的文件可能不可见。审阅不提供恢复或应用补丁操作。证据私有保存在 Host，最多保留三十天、六十四个终结执行及 512 MiB；活动审阅不会被配额清理。旧执行服务和仅本机工作区显示审阅不可用。

## 共享与路径

Linux 中的任务目录和共享目录由后台管理。Bot 可用工作区工具列出、读取、写入文件和运行命令；不同任务的目录可能不同。需要后续复用时，明确告诉 Bot 查找先前产物或共享文件，而不是猜一个旧路径。

独立屏幕不隔离这些文件。覆盖、移动或删除共享文件可能影响其他 Bot。宿主机文件不会因为存在于 Mac 或 Windows 文件夹中就自动出现在 VM，需通过附件、下载或明确的文件交换流程处理。

## 当前限制

- Windows 本机模式不提供 Linux 工作区的程序化文件、shell 和进程工具；仍可通过 GUI 使用真实文件，并处理支持的文本和图片输入。
- 文件预览不替代专业软件；大型、二进制或复杂格式可能需要下载后打开。
- 历史链接引用的是仍保留的当前文件，不是不可变的完整备份。
- 「导出工作区」不包含 Linux 文件与 VM 磁盘，见[工作区导出](workspace-export.md)。
