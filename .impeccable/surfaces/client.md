Mode: Operate. Existing visual world: the user's Grok Bot reference and the shipped local prototype. This project ports that established surface to React; it does not create a new identity or reopen layout choices. Code-led implementation uses the supplied reference, with no generated comp or external raster assets.

## Direction contract

FIRST VIEWPORT: an edge-to-edge desktop workspace with a 272px pale sidebar, compact colored Bot identities, a 70px conversation header, calm neutral message bubbles, and a bottom composer. The optional right workspace occupies about 40% of the remaining width and exposes computer/files/knowledge/skills/memory/routines. No marketing hero or dashboard card grid. Chinese system typography, monochrome controls and tiny semantic status accents. Lowercase daban wordmark replaces the prototype name.

Signature interaction: switch between Bots without losing their draft or changing another Bot's takeover. The selected Bot's conversation and workspace follow together. Closing the viewer never hands control back. Human takeover is a visibly separate state with an explicit handback button.

Supporting surfaces: inbox approval rows; settings; Bot/group creation; file preview/download; editable memory; routine creation/toggle/removal; keyboard search; light/dark theme. Live Electron targets show real state and inputs; disconnected personal Bots remain chat-capable without a computer, while browser-only examples retain explicit demonstration labels. No personal profile invented.

Quality bar: native messaging-app density, readable 14px chat with comfortable line height, 44px practical click targets where possible, no icon-only controls without accessible names, no horizontal overflow at 1024/1280/1440. Narrow web preview collapses panels rather than compressing three columns. This is not a mobile app implementation.

Verification: state/UI tests using synthetic content; TypeScript; Vite production build; desktop/compact/dark and narrow web screenshots; keyboard dialog and interaction checks. Electron runs from a production file build with actual local Linux/DSH integration; native installers and first-run VM provisioning are deferred. Current evidence includes real desktop actions, text attachments, separate handoffs, shared demonstration login and durable recovery.
